## 1. Результаты браузерного аудита (Diagnosis Findings)

В соответствии с требованиями Фазы R1 проведено тестирование 4 типов реальных страниц портала и панели редактора на 6 контрольных разрешениях (320, 375, 768, 1024, 1280, 1536 px) с фиксацией метрик и скриншотов (`r1_diag_*`):

### 1.1. Выявленные проблемы и коренные причины (Root Causes)

1. **Коренная причина предпросмотра в редакторе (Editor Device Toggle Root Cause)**:
   - В текущей реализации (`canvas-grid.tsx`) переключатель устройств (Desktop, Tablet, Mobile) изменяет лишь CSS-свойство `max-width` родительского контейнера холста (`max-w-[375px] mx-auto` или `max-w-[768px] mx-auto`).
   - Браузерное окно при этом остаётся десктопным (1440px+). Все CSS медиа-запросы (`@media (min-width: 768px)`, `md:`, `lg:`) продолжают срабатывать на реальную ширину окна браузера.
   - В результате контент внутри 375px и 768px фрейма отображается с десктопными стилями (десктопные отступы, сетки, текст), сжимаясь и искажаясь.
   - **Решение**: Редактор переводится на реальную ширину рендеринга (встроенный iframe страницы превью с точным соответствием медиа-запросов и slider 320–1536px, дополненный CSS Container Queries `@container` на уровне ячеек сетки).

2. **Горизонтальное переполнение (Horizontal Overflow +21px на 1024px)**:
   - На ширине 1024px обнаружен скролл `+21px` на всех страницах (`scrollWidth = 1045px`).
   - **Причина**: В `header.tsx` при срабатывании `lg:block` на 1024px горизонтальное меню из 7 пунктов с паддингами `px-3` и `whitespace-nowrap` превышает доступную ширину контейнера, вызывая горизонтальную прокрутку всей страницы.
   - **Решение**: Адаптивные отступы и размер шрифта меню (`text-xs xl:text-sm px-2 xl:px-3`), перенос второстепенных ссылок либо переключение на мобильное меню до достижения 1024px с гарантией отсутствия горизонтального скролла.

3. **Слишком мелкий базовый шрифт на мобильных устройствах (< 16px)**:
   - На экранах 320px и 375px базовый шрифт параграфов составляет 14px (`text-sm`), что нарушает стандарт комфортного чтения на смартфонах без зума.
   - **Решение**: Внедрение плавной типографики через CSS `clamp()` с минимальным размером текста `16px` на мобильных экранах.

4. **Недостаточный размер интерактивных элементов (< 24px и < 44px)**:
   - Зафиксировано от 20 до 22 элементов с размером менее $24 \times 24$ px (кнопки панели доступности с `py-0.5`, мелкие иконки действий) и от 36 до 49 элементов менее $44 \times 44$ px.
   - **Решение**: Обеспечение требований WCAG 2.2 SC 2.5.8 (минимум $24 \times 24$ CSS px для всех кликабельных зон) и стремление к $44 \times 44$ CSS px по SC 2.5.5 для основных элементов управления.

## 3. Модель адаптивности и точки останова (Responsive Model & Breakpoints)

Единые константы контрольных точек (определяются в `packages/shared` и прокидываются в Tailwind / CSS):
- **Mobile (`mobile`)**: $< 640\text{ px}$ (до `sm`).
- **Tablet (`tablet`)**: $640\text{ px} - 1023\text{ px}$ (`sm` и `md`).
- **Desktop (`desktop`)**: $\ge 1024\text{ px}$ (`lg`, `xl`, `2xl`).

### 3.1. Автоматическое поведение по умолчанию (Zero-edit upgrade)
Существующие страницы автоматически улучшаются без необходимости их ручного пересохранения:
1. **Mobile (< 640px)**:
   - Все ячейки ряда автоматически выстраиваются вертикально в одну колонку на 100% ширины (`col-span-12`).
   - Порядок следования в DOM строго совпадает с визуальным порядком (сверху вниз). Запрещены любые CSS-трюки с `order` или `flex-direction: column-reverse`.
2. **Tablet (640–1023px)**:
   - Ряды с 3–4 ячейками автоматически трансформируются в 2 ячейки на строку (сетка $2 \times 2$, по 6 колонок каждая).
   - Ряды с 2 ячейками остаются рядом только если каждая ячейка занимает не менее 5 из 12 колонок (например, $6+6$ или $7+5$); иначе они аккуратно стекаются друг под другом.
3. **Desktop ($\ge$ 1024px)**:
   - Полноценная 12-колоночная раскладка согласно заданным `colSpan`.

### 3.2. Переопределения по точкам останова (Per-breakpoint overrides)
В интерфейсе редактора и схеме данных:
- Настройка `colSpan` для каждого разрешения: `{ desktop: 4, tablet: 6, mobile: 12 }`.
- Настройки стилей: размер шрифта, выравнивание текста, внутренние и внешние отступы.
- Скрытие на устройствах (`hideOnMobile`, `hideOnTablet`, `hideOnDesktop`):
  - Реализуется через `display: none` (контент физически исключается из дерева доступности экранных дикторов).
  - В редакторе отображается бейдж «Скрыто на моб.».
  - Защита: контент, обязательный по [docs/UZ_COMPLIANCE.md](file:///c:/Users/Intel/Desktop/site/docs/UZ_COMPLIANCE.md) (статья 37 ЗРУ-637), запрещено скрывать.
  - Валидатор выдает предупреждение, если блок скрыт на всех трёх типах устройств.
- Наследование: любое незаданное свойство наследуется от более крупного экрана. В инспекторе отображается индикатор «Наследуется от Desktop» и кнопка «Сбросить к унаследованному».

## 4. Адаптивное поведение компонентов (Block-by-Block Responsive Specs)

1. **Hero-баннеры (`hero_banner`, `hero_split`)**:
   - На мобильных текст и медиа выстраиваются вертикально без изменения порядка DOM.
   - Высота уменьшается с десктопных 450–600px до комфортных 280–360px на смартфонах.
   - Подложка с достаточным контрастом для чтения текста поверх фона.
2. **Изображения и фокальная точка (`image_text`, `image_carousel`)**:
   - Пресеты пропорций `aspect-ratio`: `original`, `16:9`, `4:3`, `1:1`, `3:4`.
   - Настройка фокальной точки `focalPoint: { x: number, y: number }` (0–100%) в `object-position`, чтобы при кадрировании на смартфонах главный объект всегда оставался в фокусе.
   - Использование атрибутов `sizes` для предотвращения скачков макета (CLS).
3. **Сетки карточек и списки (`cards_grid`, `staff_cards`, `specialties_list`, `latest_news`)**:
   - Автоматический расчет колонок по ширине контейнера ячейки через Container Queries:
     - Container $\ge 900\text{ px}$: 3–4 колонки.
     - Container $600–899\text{ px}$: 2 колонки.
     - Container $< 600\text{ px}$: 1 колонка.
   - Равная высота карточек в ряду (`h-full flex flex-col justify-between`).
4. **Таблицы данных (`table`)**:
   - Оборачиваются в доступный горизонтальный скролл-контейнер:
     `<div class="overflow-x-auto" tabindex="0" role="region" aria-label="Jadval maʼlumotlari">`.
   - Вся страница никогда не скроллится вбок; скроллится исключительно область таблицы с видимой подсветкой краёв.
5. **Вкладки (`tabs`)**:
   - На узких экранах полоса вкладок плавно скроллится по горизонтали с градиентным намёком на продолжение, сохраняя строгий ARIA-паттерн (`role="tablist"`, `role="tab"`).
6. **Карусели (`image_carousel`)**:
   - Видимая кнопка паузы по WCAG 2.2.2.
   - Отключение автопрокрутки по умолчанию и при `prefers-reduced-motion`.
   - Поддержка свайпа жестами на сенсорных экранах (`touch-pan-y`).
7. **Кнопки и ссылки**:
   - На мобильных экранах основные CTA-кнопки растягиваются на всю ширину ячейки (`w-full`).
   - Минимальный размер области касания $\ge 44 \times 44\text{ CSS px}$.
8. **Шапка и подвал (Site Chrome)**:
   - Полная доступность и отсутствие горизонтального скролла от 320px.
   - Мобильное меню с ловушкой фокуса, закрытием по `Escape` и блокировкой скролла body при открытии.
